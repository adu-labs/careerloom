# Careerloom：逐功能实现与 Review 规划

更新：2026-09-21。用户已授权按既定技术栈开始实施。本文是当前执行顺序，范围与详细任务仍以 [总体规划](plan.md)、[任务清单](todo.md)、[Agent 工作台任务](agent-workspace.md)、[扩展任务](extension.md)为依据。

## 1. 交付方式

每次选择一个可独立验证的功能：先明确验收 → 编码及中文注释 → 必要测试 → 提交实现审阅文档 → 用户 review → 修订或通过 → 转换为教学文档。测试成功不等于用户批准。代码进入短期功能分支，用户通过前不自动合并 main、不发布生产服务、不删除审阅文档。

每项最终交付都有源码入口、实际验证记录、未完成项和审阅基线。按照根目录 [AGENTS.md](../AGENTS.md)，只有用户明确通过后才进行教学文档转换。教学目标是能够独立从零构建，不只是知道代码放在哪。

## 2. 首批工程任务拆分

原 T01 的 API/Web/数据库分别 review，不再用一个“脚手架”任务掩盖多种验收。

| 项目 | 交付与验收 | 前置 | 状态 |
|---|---|---|---|
| T01a API启动与存活检查 | 固定依赖；Nest API可启动；环境配置失败明确；存活接口、404、关闭与端口冲突有测试 | 无 | 实现与8项检查完成，待用户review |

| T01c 数据库本地环境与就绪检查 | PostgreSQL启动、连接、关闭；数据库不可用时readiness失败，但liveness仍反映进程存活 | T01a通过 | 未开始 |

T01a 主要逻辑限定为配置、应用装配、入口和两份测试文件；额外 package/tsconfig 为必要工程配置。T01b/T01c 实施前列出对应不超过5个主要逻辑文件和独立审阅文档。T01父任务只有三个子项都验收通过才算完成。

当前开发环境：Node.js 24.14.0，Python 3.10.11，未发现 Docker CLI。T01a 不依赖 Python/Docker；后续 RenderCV 所需 Python 版本和数据库运行环境在对应任务准备，不在本项中修改系统环境。

## 4. 每项审阅与完成标准

- 有具体成功与失败验收；外部供应商不可用时明确哪些能力未验证，不用假数据替代后宣称完成。
- 关键函数、状态、权限、事务／幂等与异常处理有足够中文注释；不要求每行代码翻译。
- 有已执行测试与复现命令；写入 `docs/implementation-review/<任务ID>-<功能>.md`。
- 用户通过后再创建 `docs/learning/` 对应教程，更新链接、删除临时审阅文档，保留Git历史。
- 明确当前实现、待review、已通过和生产上线的区别，按功能保留进度，不虚构完整平台交付时间。
