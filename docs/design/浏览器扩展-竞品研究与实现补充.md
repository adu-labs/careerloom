## 1. 结论与对原计划的修正

扩展应成为工作台在外部招聘网站上的入口，覆盖**发现岗位 → 私人收藏 → 选择简历版本 → 填写复核 → 确认投递记录 → 后续面试**。原 T51 只有“受控填表试验”，不足以覆盖正式产品；保留其验证作用，新增独立交付任务。

但不能把“填表与工作台连通”当作独有卖点：OfferLink 官网已经公开介绍职位发现、JD 识别、资料管理、自动填写与进度记录的组合。因此差异化应落在可验证的质量：中文复杂表单适配、指定简历版本与显隐一致、写入前后可解释、用户覆盖值不被改掉、投递材料可追溯，以及与复盘和面试准备衔接。[OfferLink 官网](https://offerlink.tech/)。

现有材料足以决定产品方向，不能证明哪款实际填写最准确，也不能判断其他产品一定没有某项能力。下一步比较应使用同一份合成简历、同一组受控表单和统一计分口径。

## 3. 我们的扩展产品定义

### 3.1 侧边栏是主界面

点击扩展打开侧边栏，保持招聘页面可见，提供“当前岗位、填写简历、投递记录”三个视图。页面内小按钮只作为可关闭的快捷入口，不遮挡原站操作。切换标签页后明确当前公司、岗位、网址和已选材料；不能把上个页面的简历写进新页面。

工作台负责完整编辑、版本历史、模板、日程、复盘与交易。扩展负责当前页面的识别和操作，不再建一套独立简历编辑器和独立账号资料库。

### 3.2 七项正式能力

| 能力 | 产品行为 | 失败与边界 |
|---|---|---|
| 收藏当前岗位 | 识别公司、职位、城市、JD、官方来源和时间，用户确认后写入私人机会 | 不发布公共招聘；未知字段保留空白；脱敏 URL 查询参数 |
| 选择材料 | 选择计划、简历、明确版本，展示语言与隐藏条目数量 | 不自动用最新版替换本次版本；简历修改后提示是否重新载入 |
| 辅助填写 | 识别字段 → 映射 → 预览 → 执行 → 读回检查 | 未匹配、低把握、原值冲突分别列出；保留用户手填内容 |
| 开放题辅助 | 对“为什么选择公司”等问题生成草稿，显示依据，可改后插入 | 不编造经历；薪资、到岗、调剂等意愿由用户确定 |
| 浏览筛选 | 根据本人规则折叠已投岗位、屏蔽公司／关键词、提示疑似重复 | 展示折叠原因和数量，一键恢复；不把疑似重复永久隐藏 |
| 投递确认 | 用户提交后确认岗位、时间、渠道和材料，形成投递记录 | 填写完成或点击提交均不直接当作成功；无回执时标记用户自报 |
| 失败反馈 | 展示不支持控件、手工复制入口，允许用户提交最小化诊断 | 不默认上传整页、完整简历或截图；反馈前可预览去标识信息 |

实习／校招侧重教育、项目、校园经历与多段表单；社招侧重工作经历、岗位版本、期望条件和猎头来源。但所有阶段均可手动编辑资料，不能因阶段自动补造信息。

### 3.3 网申资料不能只等于 PDF 简历

网申常见的到岗时间、工作地点偏好、资格问题不一定写在简历里。增加 **ApplicationProfile（网申资料）**，与简历内容分开：可复用事实、阶段／计划偏好、本次申请回答三层。联系方式等字段有来源和更新时间；本次回答不自动覆盖长期资料。

字段取值优先：本次明确选择 > 已选简历版本中的可用事实 > 用户明确授权的网申资料 > 未填写。简历里隐藏的经历不得由经历库或旧网申资料补回。来源冲突时询问该字段，禁止静默猜测。敏感或非必要信息不因招聘页面存在字段就默认收集。

扩展不需要读取 JSON、LaTeX、YAML、Typst 本身，而应获取该版本经过授权的结构化投影。自由源码简历若尚无经用户确认的结构化数据，先显示解析草稿供核对，不能只凭 PDF 文本直接执行填写。

### 3.4 写入与撤销不是网页事务

预览显示“字段、页面原值、拟填值、来源、处理状态”。默认只填空白字段；覆盖已有值逐项确认。运行中页面跳转、表单结构变化、用户同时输入均暂停相关字段。

本次会话保存写入前值与写入后值；撤销时只有页面当前值仍等于本扩展写入值，才恢复旧值，避免覆盖用户后续编辑。动态删除的表单项、页面刷新或招聘站自动保存不保证可撤销；明确提示需到原站核对。填表本身可能触发原站自动保存，因此不是“最终提交前完全没有向网站发送信息”。

附件选已冻结 PDF，显示名称、语言、版本与页数。默认由用户在原站文件选择器上传；只有通过专项验证的站点才提供辅助文件上传。文件上传成功、表单保存成功、最终申请成功是三种状态。

## 4. 识别与执行的技术设计

采用 Manifest V3，优先 Chrome 与 Edge 分别验收、分别发布；其他 Chromium 浏览器不能仅凭同内核宣称支持。Firefox／Safari 作为后续兼容工程，不能沿用同一套测试结论。

建议组件：侧边栏 UI、content script 页面观察与操作、service worker 事件协调、后端授权与 AI 接口、版本化站点 adapter。侧边栏依据 Chrome 的 [Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)；不支持时退化到扩展页。

### 4.1 规则优先，AI 辅助语义映射

1. 验证域名与当前页面属于用户启动的会话，读取表单的 label、name、占位提示、可选值、分组关系和必要 DOM 结构。
2. 已验证站点 adapter 处理多段经历、增删行、联动选择器、日期等控件；通用规则处理标准输入。
3. 无法映射的字段送最小化 schema 给模型判断含义；个人字段值尽量在本地映射，长文本生成单独授权。
4. 返回受约束的操作计划，如 `setText`、`chooseOption`、`appendExperience`；目标限定于本次发现的表单字段，模型不能返回任意 JavaScript、外链请求或页面脚本。
5. 用户确认，执行前检查 DOM 版本与原值；写入后触发适当控件事件并读回检查。DOM 值改变但原站框架未接受，不算成功。

iframe、开放／封闭 Shadow DOM、自定义上传、虚拟列表与跨域表单分别标记支持度。跨域 iframe 需要相应授权；访问不到或控件不可操作时降级手填，不宣称万能识别。截图视觉识别仅作为可选后续路径，需额外授权和脱敏设计。

### 4.2 最小权限与身份连接

用户触发的页面识别优先使用 `activeTab` 与 `scripting`；持续站点筛选另申请指定域名的可选权限，不能把 activeTab 误当成所有网页的长期访问权。[Chrome activeTab 文档](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)。

扩展使用独立、可撤销、限 scope 的服务端凭证，默认仅允许读取本人选定版本、创建私人机会／投递记录。通过可信登录流程交换凭证，校验 state／PKCE 与回调来源；凭证不放页面 DOM，不信任任意页面的 postMessage，后台校验消息来源、tab、frame 和会话。

不申请全浏览历史、浏览器 cookies 或所有网站永久权限作为默认前提。内容脚本只能接触本次投影，不能读取整个经历库。退出登录、账号切换、会话到期清理缓存；保存少量恢复数据时设 TTL，不将简历正文同步到浏览器厂商同步存储。

### 4.3 状态可恢复与适配器更新

MV3 service worker 可能被终止，不能把执行进度和唯一会话状态只存在内存。用持久化任务 ID、版本 ID、字段操作序号和幂等键恢复；重启后重新验证页面再执行，不能无条件续填。[官方生命周期文档](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

适配器代码随扩展商店版本发布。远端仅下发严格 schema 的数据配置和关闭开关，不下发 eval、脚本 URL 或足以执行任意程序的指令；签名校验不等于可以远程执行代码。[Chrome 远程代码规则](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code)。站点变化时先关闭坏适配，展示已知问题，再更新验证版本。

## 5. 工作台数据与接口补充

新增：ApplicationProfile、ExtensionSession、FieldMapping、FillRun、SiteAdapterVersion、BrowsingRule、SubmissionObservation。FillRun 记录使用的 resumeRevision、网申资料版本、站点／表单摘要、填写差异、确认时间和错误，不长期保存整页 DOM。

建议接口：

- `POST /v1/extension/sessions`：创建限域会话与能力清单。
- `GET /v1/extension/resume-projection`：只返回指定版本本次允许字段，检查显隐和权限。
- `POST /v1/extension/opportunities`：经确认收藏至私人机会，幂等去重。
- `POST /v1/extension/fill-runs`：记录运行摘要，不因运行成功更新申请状态。
- `POST /v1/extension/submission-observations`：保存用户自报或识别回执；最终由确认规则决定 ApplicationEvent。
- `GET/PATCH /v1/extension/browsing-rules`：默认本地规则，可选同步本人账号；不收集浏览历史来实现过滤。

如果填表后用户又在原站修改，记录中的“拟填写快照”不应冒充“最终提交内容”。有最终复核记录才保存最终确认快照；否则明确材料内容未完全核实，已投递文件版本与表单填写值分别记录。

## 6. 支持范围与验收方法

首先按表单引擎和业务流程组织适配，再关联公司站点。候选包括企业自建官网，以及 Moka、北森、飞书招聘等常见系统；这里只是待验证目标清单，不是已支持声明。互联网技术岗位优先，其他行业不影响技术架构但不挤占首批验证资源。

每个适配记录域名、流程、引擎、adapter 版本、最后验证时间、支持控件、已知限制和反馈入口。不同公司的同类系统也可能配置不同，不能验证一家公司便宣称全系统通用。

建议首批 12 套合成表单：文本、radio、普通 select、搜索下拉、级联城市、月份日期、重复经历、多步骤、SPA 重绘、iframe、Shadow DOM、文件上传。每种至少包含原值冲突、缺失数据或页面变更样本。随后用虚构资料在获允许的测试／预览页面验证真实布局，不创建虚假求职申请。

上线门槛：支持范围内合成集姓名、电话、邮箱、学历、时间等关键字段不得出现静默错填；隐藏经历泄露为零；非授权自动提交为零；不支持项有明确反馈。字段正确率、可自动填写覆盖率、整表可用率分别统计，失败和跳过不能从分母中偷偷删除。人工修正次数和节省时间通过受控对照测量，不沿用竞品“秒填”“提升300%”宣传。

## 7. 资源利用与商业判断

这六款作为产品研究资料，不代表开源代码资源。当前没有核实可供我们调用的公开 API／SDK 或再分发授权，因此不规划将第三方闭源插件直接嵌入自己平台。可借鉴交互和公开能力，若后续合作再核验接口、数据范围、费用及维护责任。

扩展可承载免费基础收藏／受支持字段填写，AI 开放题和大量定向优化按实际成本配置权益；准确性提示、撤销和用户数据导出不能作为付费解锁项。收费方案是待验证设计，不能因为商店有内购就推断其商业成功。

现阶段优先完成接口与受控表单验证，并将真实扩展交付推进到简历、岗位工作流阶段；不等全部商业模块完成后才开始适配。完整平台验收仍要求扩展与投递快照联通。


## 8. 国内优先与海外、英语适配

当前以国内企业官网和招聘系统为主。adapter 从开始就将字段语义、显示语言和站点操作分开：同一个教育字段可对应中文或英文标签，但学历选项映射仍需地区确认。海外阶段逐站验证英文表单、海外招聘流程和资格问答；工作许可、签证支持和搬迁意愿一律由用户确认，不自动推断。

侧栏后续随工作台支持英文，简历语言可独立选择；岗位收藏保留原文与语言，AI 翻译是可选视图。英文页面并不自动代表海外岗位。支持清单按站点、语言、地区和最后验证时间公布，Chrome/Edge 兼容不能代替站点兼容验收。对应工程任务 I04，依赖 E09 的权限与运行可靠性底座。
